# チケットの実装を締めくくる

> いつ使うか: チケットの実装が終わり、PRを出す前。

## 入力
| 入力 | 例 | 必須 |
| :--- | :--- | :--- |
| 現在のブランチ | `feat/12-dream-swap` | 必須（`git branch --show-current` で取得） |

## 読むファイル
1. `plan/<ブランチ名>.md`（`/` は `-` に置換）
2. このブランチの差分

## 手順
1. **仕様書**: 振る舞いを変えたなら、仕様書を更新する（`write-spec` スキル）。
2. **テスト仕様書**: plan のテスト観点を、テスト仕様書に移す（`write-test-spec` スキル）。
3. **ADR**: plan の決定事項で「ADR化」の印が付いたものから、ADRの下書きを作る（`write-adr` スキル）。
4. **CHANGELOG**: 利用者から見える変更（機能追加・仕様変更・不具合修正・廃止）なら、`CHANGELOG.md` の `Unreleased` の既存の見出しの下に1行で書く。内部のリファクタリング、テストやドキュメントだけの変更は書かない。バージョン番号は付けない（リリース時に人間が付ける）。
5. **その他の文書**: 構成や共通部品を変えたなら `docs/architecture.md`、監視やデプロイ手順を変えたなら `docs/operations.md` を更新する。
6. **plan のアーカイブ**: plan ファイルを `plan/archive/` へ移す（同じPRに含める）。
7. **確認**: `README.md` の「確認」コマンドを実行する。
8. **自己レビュー**: `review-pr` スキルで差分を確認する。
9. **セルフレビューの記録**: `.git/ai-review-log.jsonl` から、現在のブランチの行を読む（`git rev-parse --git-common-dir` で場所が分かる）。コマンドごとに最後の記録を使い、PRの「セルフレビュー」欄を埋める。
   - 記録が無いコマンドは「未実行」と書く。実行を促したり、代わりに実行したりはしない。
   - 「その後のコミット数」は `git rev-list --count <記録のコミット>..HEAD`。記録の `uncommitted` が true なら、「未コミットの変更を含む状態で実行」と添える。
   - 「指摘と対応」は、この会話の中で結果を見た場合だけ書く。見ていなければ「不明」と書く。
10. `project.md` 2.4 の段階的な移行の途中なら、最後の削除の Issue があることを確かめる。

## 出力
PRの説明（`.github/PULL_REQUEST_TEMPLATE.md`）を埋め、次も報告する。
- 更新した文書の一覧
- CHANGELOG に追記したか、追記不要と判断したか
- `TODO(AI_UNSURE)` が残っていればその一覧

## やってはいけないこと
- plan に書かれていない仕様を、文書に書き足す。
