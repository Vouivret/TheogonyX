# 画面と多言語対応のルール

> `.agent/rules/project.md` の下位ルール。矛盾した場合は `project.md` を優先する。
> 対象: Godot の UI（Control ノードのシーンとスクリプト）と、文言の翻訳ファイル（`project.md` 0章の表を参照）。コンパニオンの画面のルールは、技術が決まったらここに追記する。

## テーマ
- 使う仕組み: Godot の Theme リソース。
- 色・余白・フォント・文字サイズの定義場所: `game/ui/theme/`（全体のテーマは `game/ui/theme/main_theme.tres`）。
- UI はテーマと `game/ui/common/` の共通シーンで組み立てる。ノードごとの上書き（Inspector の `theme_override_*`、コードからの `AddThemeColorOverride` など）で色や余白を直書きしない。
- 既存のテーマや共通シーンで表現できない場合は、作る前に、何が足りないかを報告して確認する。

## ピクセルアートの表示
- UI のアイコンやフォントはピクセルアートの見た目を保つ（テクスチャのフィルタは Nearest）。プロジェクト設定のフィルタやスケールの設定を変えるときは確認する。

## 多言語対応
- 画面に出す文字列をコードやシーンに直接書かず、`game/locales/` の翻訳ファイル（CSV）にキーで置く。シーンではキーをテキストに入れ、コードでは `Tr("KEY")` で取り出す。
- 文字列を連結して文を組み立てない。語順は言語ごとに違うので、プレースホルダ付きの1つの文として登録する（例: `Tr("DOGMA_PREFIX") + symbolName + Tr("DOGMA_SUFFIX")` ではなく、`{0}は禁忌となった` を1つのキーで登録し `string.Format(Tr("DOGMA_FORMED_TABOO"), symbolName)` と書く）。
- 新しいキーを追加したら、`docs/nfr.md` に書かれた対応言語すべての列に追加する。翻訳できないものは原文を入れ、未翻訳であることを報告に書く。
- 年・数値は、.NET のロケール対応の機能（`CultureInfo`）で整形する。自前で整形しない。
- 訳語は `docs/domain/glossary.md` に合わせる。記号（シンボル）の表示名もキーで管理する。
- ログと例外メッセージは翻訳の対象にしない。
