# セーブデータとゲームデータ定義のルール

> `.agent/rules/project.md` の下位ルール。矛盾した場合は `project.md` を優先する。
> 対象: セーブデータの読み書きと、記号・ドグマの閾値などのゲームデータ定義（`project.md` 0章の表を参照）。

## ゲームデータ定義
- 記号の定義、ドグマ判定の閾値、環境の変化量などの調整値は、コードに直書きせず `game/data/` のデータファイル（JSON か Godot の Resource）に置く。コアはデータを引数で受け取り、ファイルを直接読まない。
- データ定義のID（例: `SYM_TREE`）は、一度セーブデータに書かれうる状態になったら変更・再利用しない。廃止するときは定義を残して廃止の印を付ける。
- データファイルの値を変えるのは、ゲームのルールの変更である。依頼に値が含まれていなければ確認する（`project.md` 4章）。

## セーブデータ
- セーブデータには形式のバージョン（`saveVersion`）を持たせる。
- 最初の配布（体験版を含む）より後は、配布済みのバージョンのセーブデータを読めなくする変更をしない。形式を変えるときは `saveVersion` を上げ、古い形式から新しい形式への変換処理を追加する。配布済みの変換処理は変更も削除もしない。
- 配布前（Phase 1）は互換性を保たなくてよいが、形式を変えたら `saveVersion` は上げる。
- セーブデータの形式の変更と、既存のセーブデータの変換は、処理の流れを先に示す対象である（`project.md` 2.3）。
- 書き込みは、一時ファイルに書いてから置き換える。書き込みの途中で終了しても、前のセーブデータが壊れないようにする。
- 読み込んだセーブデータは外部入力として扱う（利用者が手で書き換えうる）。壊れていたら例外で止めず、読めないことを利用者に伝える。

## テスト
- 変換処理を追加したら、古い形式のセーブデータのサンプルを `tests/` に置き、読み込んで変換できることを確かめるテストを書く。
