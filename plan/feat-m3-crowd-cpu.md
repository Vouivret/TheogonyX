# plan: M3 群衆（CPU 版とポテンシャルフィールド）

## 目的
地表に 10,000 人の群衆を点で描き、ポテンシャルフィールドに沿った散策・聖地への狂乱・崩壊での停止を見せる（[crowd.md](../docs/domain/crowd.md)、[ロードマップ](../docs/roadmap.md) の M3）。この段階では CPU（コア）で計算する。GPU 版（Compute Shader）は次の plan で足し、この CPU 版と突き合わせる。

## スコープ
- 含む
  - コアの群衆の計算（始めの配置・状態の判定・散策・狂乱・停止・世界再創生）とポテンシャルフィールド
  - `MultiMeshInstance2D` での点の描画（1 回の DrawCall）
  - `rules.json` の `crowd` に調整値を置く（仮の値、`TODO(AI_UNSURE)`）
- 含まない
  - Compute Shader 版と、GPU・CPU の突き合わせ（TS-crowd-009）、60fps の計測（TS-crowd-011）: 次の plan
  - Boids・衝突回避、群衆の位置のセーブ

## 決定事項
| 決定 | 理由 | ADR化 |
| :--- | :--- | :--- |
| 群衆は見た目だけ。10,000 人、1〜2 px の点。散策・狂乱（カオス度 50 以上）・停止（崩壊）。聖地は予言者の足元 | 人間が決めた（2026-10-12） | しない |
| 散策では、水場・草地・密林が引き寄せ、砂漠・氷河・焦土が遠ざける（焦土が一番強い）。狂乱では聖地の引力だけ | 人間が決めた（2026-10-12） | しない |
| **AI の案**: 乱数は `System.Random` ではなく、(シード, 人の番号, 歩数) から作るハッシュ関数（整数の演算だけ）にする | GLSL で同じ関数を書けば、GPU 版と同じ乱数になる。`System.Random` は GPU で再現できない。`csharp.md` の「乱数は `System.Random`」から外れるので ADR に残す | 済（[0004](../docs/adr/0004-crowd-counter-based-hash-random.md)） |
| **AI の案**: 位置・速さはタイルの単位（1 = 16 px）で持つ。地表は 0 ≦ x ≦ 16、0 ≦ y ≦ 9 | コアにピクセルの大きさを持ち込まない。AC-crowd-002 の範囲もタイルの単位に書き直す | しない |
| **AI の案**: 固定の歩幅（1/60 秒）で進める。1 フレームに進める歩数は 8 まで（遅れた分は捨てる。高速の 3 倍でも 30fps まで追いつける） | 同じ歩数なら同じ結果になる（決定性）。遅いフレームで計算が雪だるま式に増えない | しない |
| **AI の案**: ポテンシャルフィールドは、マスごとに「他の全マスの (力 − 全マスの力の平均) × そのマスへの向き ÷ (1 + 距離)²」の和を、タイルが変わったときだけ作る。人は自分のいるマスの力を受ける | 地表が一様（すべて草地など）なら力が 0 になり、中央に寄り続けない。マスは 144 なので作り直しは軽い。GPU では小さなテクスチャで渡せる | しない |
| **AI の案**: 散策の向きは、人ごとに時期をずらして、決まった間隔で乱数で選び直す | 全員が同時に向きを変えると不自然 | しない |
| **AI の案**: 狂乱では、人ごとに聖地の周りの範囲（地表の上の半円）の中の 1 点を乱数で決め、そこへ向かう。着いたら止まる | 全員が 1 点に重なると点が 1 つに見える | しない |
| **AI の案**: 聖地の位置は、予言者の列（`prophet.column`）と絵の幅（2 タイル）から、予言者の左右の中央・地表の上端とする | 予言者の位置の決め方（[ambience.md](../docs/domain/ambience.md)）と同じ | しない |
| **AI の案**: 描画ノード `Crowd`（`MultiMeshInstance2D`）を `main.tscn` の `WorldViewport` の下、`Terrain` の直後に手で足す | 環境光（`CanvasModulate`）がかかり、HUD の下に描かれる。`unique_id` はエディタで保存して付けてもらう | しない |
| **AI の案（仮の値）**: 歩く速さ 0.5 タイル/秒、向きを変える間隔 2 秒、狂乱の速さ 2 タイル/秒、聖地の周りの範囲 1.5 タイル、力の強さ 水場 1.0・密林 0.6・草地 0.4・砂漠 −0.6・氷河 −0.6・焦土 −1.0、力の倍率 0.5、点 1 px・色 `#D2AA99` | 実際に見て決める（`TODO(AI_UNSURE)`） | しない |

## 処理の流れ

### 作る（`WorldCore._Ready`）
- `rules.json` の `crowd` を読む。人数が 1 以上、速さ・間隔・範囲が正の有限の数、力がすべてのタイル種別にあることを確かめ、違えば読み込みを失敗にする。
- `Crowd` をシード（セーブにあればその値）と聖地の位置で作る。始めの配置は、人ごとに (シード, 番号) のハッシュから地表の中の位置を決める。向きも同じく決める。
- ポテンシャルフィールドを今の地表のタイルから作る。

### 毎フレーム（`CrowdView.Process(delta)`）
- 時間の操作から群衆の時間の倍率を決める（`Crowd.TimeScaleOf`）: 自動進行中でなければ 0（何もしない）、高速なら `fastTimeScale`、それ以外は 1。人間が決めた（2026-10-12）。
- 経過時間 × 倍率を足し、1/60 秒ごとに 1 歩進める（1 フレームで 8 歩まで。それより多くたまった分は捨てる）。
- 歩くたびに、今の星の状態から状態を判定する: 崩壊 → 停止、カオス度 ≧ 閾値 → 狂乱、それ以外 → 散策。
  - 停止: 何もしない（歩数も進めない）。
  - 散策: 人ごとに、向きを変える時期なら乱数で向きを選び直す。速さ = 向き × 歩く速さ + いるマスの力 × 力の倍率。位置を進め、地表の端を越えたら跳ね返す（位置を折り返し、向きを反転する）。
  - 狂乱: 人ごとの目的の点へ、狂乱の速さで進む。1 歩で届くなら目的の点に置く。
- 全員の位置を `MultiMesh` のバッファに書き込む（タイルの単位 × 16 px）。

### タイルが変わったとき（`WorldScreen.Refresh` の後）
- 地表を描き直したのと同じ `ClassifyTiles` の結果から、ポテンシャルフィールドを作り直す。

### 世界再創生
- 群衆を始めの配置・向きに戻し、歩数を 0 にする。状態は次の歩で判定し直す。

### セーブ・ロード
- 群衆はセーブしない。ロードした後は、そのシードの始めの配置から動き出す。
