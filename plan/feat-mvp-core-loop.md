# plan: MVP コアループ（夢の改ざん → ドグマ生成 → 時代跳躍 → 環境変化）

## 目的
Godot 4.7.2（C#）上で、夢を改ざんするとドグマが生まれ、100年後の星の環境が変わる、というコアループが動くことを確かめる（`PROMPT_FOR_CLAUDE.md` の最初のマイルストーン）。

## スコープ
- 含む
  - ソリューションとプロジェクトの骨組み（`TheogonyX.sln`、`src/TheogonyX.Core/`、`tests/TheogonyX.Core.Tests/`、`game/`）
  - 夢の解釈（[仕様書](../docs/domain/dream-interpretation.md)）
  - 時代跳躍（[仕様書](../docs/domain/time-skip.md)）
  - MVP の記号と調整値のゲームデータ定義（`game/data/`）
  - Godot のノード `WorldCore` が、改ざん前後と100年後の状態をログに出すシナリオ
- 含まない: 描画（タイルマップなど）、UI、問解、コンパニオンとの通信、セーブデータ、狂信度・感染

## 決定事項
| 決定 | 理由 | ADR化 |
| :--- | :--- | :--- |
| コアは `net10.0` のクラスライブラリ `TheogonyX.Core`。Godot に依存しない | xUnit で Godot なしにテストするため（`csharp.md`） | する |
| Godot プロジェクトは `game/` に置き、`game/TheogonyX.csproj`（`Godot.NET.Sdk/4.7.2`、`net10.0`）からコアを `ProjectReference` で参照する | 直下に置くと、Godot が `src/`・`tests/` の `.cs` までビルドに含めるため | する |
| テストは xUnit。パッケージは `dotnet new xunit` の既定のものを使う | 追加の依存を増やさない | しない |
| 記号・極性・種別の閾値・環境の変化量・値の範囲・崩壊条件は `game/data/symbols.json` と `game/data/rules.json` に置く。コアはこれを読み込んだ定義オブジェクトを引数で受け取る | 調整値を直書きしない（`save-data.md`） | しない |
| JSON の読み込みは `game/` 側で `System.Text.Json` を使う | 標準ライブラリで足りる | しない |
| 極性の和を閾値と比べる前に、和を小数第4位で丸める（`Math.Round(和, 4)`） | float で 0.6 + (−0.9) が −0.29999995 になり、−0.3 以下の判定から外れるため | しない |
| `project.godot` と `main.tscn` は、AIが `uid` を書かない最小の形で作り、あなたが Godot で開いて保存する（Godot が `uid` を補う） | `uid` を手で作らない（`godot.md`） | しない |
| MVP は乱数を使わない | 仕様に乱数の要素が無い | しない |

## 処理の流れ

### 夢の解釈 `DreamInterpreter.Interpret(夢ノードの並び, 定義)`
- 夢ノードが2個未満 → `null` を返す（ドグマ無し）。
- 先頭から順に、隣り合うペア（i, i+1）ごとに:
  - 衝撃度 = 重み(i) × |極性(i)| ＋ 重み(i+1) × |極性(i+1)|
  - 衝撃度が、これまでの最大「以上」なら、このペアを候補にする（「以上」にすることで、同点のときは後ろのペアが残る）。
- 候補のペアについて:
  - 極性の和 = 極性(i) ＋ 極性(i+1) を小数第4位で丸める。
  - 和 ≤ 禁忌の閾値（−0.3）→ 禁忌。和 ≥ 崇拝の閾値（+0.3）→ 崇拝。それ以外 → 破壊。
  - 強度 = min(1.0, 衝撃度)。
  - 対象 = ペアの1番目の記号ID。
- ドグマを返す。

### 時代跳躍 `WorldSimulator.SimulateTimeSkip(世界の状態, ドグマの一覧, 年数, 定義)`
- 年数が負 → `ArgumentOutOfRangeException`（呼び出し側の誤り）。
- 世界がすでに崩壊している → 何もせずに戻る。
- 年数の回数だけ繰り返す:
  1. 年を1つ進める。
  2. 全ドグマについて、（対象の記号, 種別）の変化量を定義から引く。無ければ何もしない。あれば 変化量 × 強度 を項目ごとに合算する。
  3. 合算した変化量を世界の状態に加える。
  4. 各項目を定義の範囲に収める。
  5. 崩壊の条件（カオス度 ≥ 100、水資源 ≤ 0 かつ森林量 ≤ 0、気温 ≥ 70 または ≤ −40）のどれかを満たしたら、崩壊にして繰り返しを抜ける。
- 世界の状態は引数のオブジェクトを書き換える。

### Godot のシナリオ `WorldCore._Ready()`
- `game/data/` の JSON を読み込む。読めなければ、文脈を足した例外を投げる。
- 夢 木(0.5) → 雨(0.6) を作り、ログに出す。
- 2コマ目を 血(0.9) に差し替え（改ざん）、ログに出す。
- 夢を解釈し、ドグマが生まれたら一覧に加えて `event=dogma_formed` を出す。
- 100年跳躍し、`event=time_skipped` で年・森林量・水資源・気温・カオス度・調和度・崩壊の有無を出す。崩壊していたら `event=world_destroyed` を出す。
