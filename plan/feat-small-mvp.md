# plan: 小さな MVP（自由文の神託と方言の聞き違え）

- 仕様書: [神託の作り方](../docs/domain/oracle-pair.md)の「自由文の神託」「画面と通信（小さな MVP）」「祈りの言葉と語彙の見せ方（小さな MVP）」・[予言者の暮らし](../docs/domain/prophet-life.md)の「理由のある旅と、神の声の行き先」・[信仰としてのドグマ](../docs/domain/dogma-belief.md)の「小さな MVP での仮の形」・[セーブ・ロード](../docs/domain/save-data.md)の「小さな MVP のセーブ」・[AI による表現](../docs/domain/ai-presentation.md)の「自由文の神託と答えの記録」
- ロードマップ: [roadmap.md](../docs/roadmap.md)の「小さな MVP を先に作る（2026-10-17 に決定）」

## 目的
今の小さな星（32 × 18 タイル、1 列に並んだ 16 地域）のまま、新しいコアループの芯を動かし、「予言者の聞き違えが面白いか」を遊んで確かめる。
神が文で語る → 予言者が方言のように聞き違える → 掟の 1 行と聞こえた文を告げる → 近くの住人が信じ、人づてに広がる → 信者の割合だけ教えが効く → 祈りの言葉から予言者の語彙を推し量る、の一巡りを作る。量の値は遊びながら決める（仮の値はすべてデータ定義に置き、`TODO(AI_UNSURE)` を付ける）。

## スコープ
- 含む
  - コア: 語の一覧（概念の ID）、語義のずれ表（シードと器の段から作る）、聞き違え（知らない言葉・ずれ表・謎の言葉・1 か所まで）、教え 1 つと行き先 1 つを作る、方言帳、神託の記録（経典の元）。
  - コア: 予言者の居場所・知っている土地・行き先・理由のある旅（下の決定事項の範囲）。予言者の列 16 の固定をやめる。
  - コア: 住人ごとの信仰（最大 3 つ・強さ・矛盾）、最初の信者・交流とつがいでうつる・親から子へ継ぐ・忘れられる、`dogmaEffects` に信者の割合を掛ける。
  - コア: 祈りの言葉（困りごとの祈り・日々の祈り・新しい語・汚染の匂わせ）。
  - LLM: 聞き取り（文 → 概念の ID）と語り（聞こえた文と語り）の頼みの文と、答えの検証。LLM が無いときの「言葉を選ぶ」形。
  - 画面: PC の神託の欄（入力欄・語りかける・言葉を選ぶ形）、告げる吹き出し、方言帳の欄、HUD の教えと信者の人数、予言者の絵が地域を移る。
  - 通信とスマホ: `SPEAK`・`PRONOUNCE` の作り替え・`ORACLE_STATE` の作り替え・告げた言葉と方言帳の送信。
  - セーブ: 版 16。版 15 までのセーブは `save.v15.json` に残し、新しい星で始め、1 度だけ知らせる。
  - 文書: 上の仕様書の未決のうち、この plan で仮に決めたものの書き込み、受け入れ条件、テスト仕様書、`docs/protocol/messages.md`、用語集、`CHANGELOG.md`、ロードマップの状態。
- 含まない（ロードマップの範囲の外）
  - 96 地域の格子・気候・人のまとまり・発明（予言の成就）・宗教・奇跡・感情の見える化・人が思う神の姿と天命・経典の書き換え。
  - 記号「人」「知」（今のデータに無い。語の一覧にも入れない）。
  - 星の一覧・複数の星（1b。版 17）。
  - 予言者の老いと死・後継・神の沈黙・家族（段 5）。
  - 信仰で神威が溜まる形（今の 1 年に一定量のまま）。

## 作る順番
小段ごとに `README.md` の「確認」を通し、Godot で動かして確かめてから次へ進む。

1. **言葉と聞き違え（コアだけ）**: 語の一覧・ずれ表・聞き違え・教えと行き先・方言帳・神託の記録。今のゲームにはつながない。
2. **住人の信仰（コアと HUD）**: 信仰・広がり・忘れられる・効き目 × 信者の割合。今の 2 枚の神託から生まれたドグマを、そのまま信仰の元にする。HUD に教えと信者の人数。
3. **予言者の居場所と旅（コアと描画）**: 列 16 の固定をやめ、予言者の地域を持つ。広めるための旅だけで動く（行き先は小段 4）。
4. **自由文の神託への切り替え（LLM・PC の画面・セーブ版 16）**: 神託の欄を入力欄に替え、2 枚の神託をやめる。方言帳の欄。古いセーブの扱い。
5. **祈りの言葉**: 困りごとの祈り・日々の祈り・新しい語・汚染の匂わせ。
6. **スマホと通信**: `SPEAK` ほか。通信の契約の version を上げる。

## 処理の流れ

### 星を作るとき（ずれ表）
1. 予言者の器の段を決める。既定は `game/data` の段ごとの割合のうち、「祭司」（2 割）とする（スペックからの選び方は下の未決）。星を作る画面が無いので、この MVP では設定ファイルで変えられる形にする。
2. 星のシードから、ずれ表専用の乱数を作る（住人・建物の乱数と分ける）。
3. 語の一覧（名詞は記号ごと、動詞は種別ごと）を ID の順に並べ、語ごとに、器の割合の確率で「ずれる語」にする。
4. ずれる語ごとに、ずれ方を決める。
   - 動詞: 確率（仮）で「良い・悪いの反転」（崇拝 ↔ 破壊）、それ以外は「種別が変わる」（ほかの種別の動詞から 1 つ）。
   - 名詞: 隣の記号（結びつきの表）の名詞から 1 つ。隣が今のデータに無い記号（人・知）だけなら、ずれない語にする。
5. 表はセーブに残し、読み込んだときはシードから作り直さない。器の段は星の途中で変えない。

### 語りかける（LLM が使えるとき）
1. 文を受け取る（PC の欄か `SPEAK`）。空・上限（仮 80 字）を超える・制御文字を含む文は捨て、理由を返す。崩壊している・神威が足りない・聞いている途中なら、受け付けない（理由: `star_destroyed`・`not_enough_faith`・`already_listening`）。
2. 聞いている状態にする。吹き出しに「予言者は耳を澄ませている…」を出す。自動進行中なら止め、「語りかけで止めた」を覚える。文はログに出さず、`event=oracle_speak_received textLength=…` だけを出す。
3. **聞き取り**（LLM 1 回目）: 神の文と、全部の名詞・動詞の一覧（ID と表示の語）、方角の一覧を渡す。答えは JSON で、名詞の ID（無ければ null）・動詞の ID（無ければ null）・行き先（東・西・北・南・土地の名・なし）・謎の言葉（文字列の一覧）。
4. 答えを検証する。形の崩れ・一覧に無い ID・長すぎる謎の言葉は失敗とする。名詞も動詞も行き先も無いときは、LLM に全部の記号から一番近い名詞を選ばせた答え（同じ答えに入れさせる）を使う。それも無ければ失敗とする。
5. 失敗（つながらない・時間切れ・検証を通らない）なら、書いた文を残したまま「言葉を選ぶ」形に替え、下の「言葉を選ぶ」へ。`event=oracle_hear_failed reason=…` を `Warn` で出す。聞いている状態は解き、神威は使わない。
6. **知らない言葉**: 名詞の記号が手札に無ければ、聞き違え先を決める。答えの「知らない言葉の聞き違え先」を、手札にある記号のうち、その記号自身と隣の記号の名詞の中から選ばせておく（3 の答えに入れさせる）。その中に無い ID なら失敗とする。隣にも手札の記号が無ければ、手札の全部の記号から選ばせる（仕様書の「語彙に近い言葉が無いとき」）。
7. **ずれ表**: 6 で聞き違えが起きていなければ、動詞、次に名詞の順に、ずれ表に当たる最初の 1 つだけをずらす。
8. **教え**: 聞こえた名詞の記号 × 聞こえた動詞の種別 × 動詞の強度。名詞が無ければ教えは作らない（行き先だけの神託）。動詞が無ければ、仮の既定の種別（崇拝）にする（`TODO(AI_UNSURE)`）。
9. **行き先**: 東・西はそのまま。北・南・土地の名は「なし」に聞き違える。
10. 答え（ID・聞き違えの中身・行き先・謎の言葉）を命令にして積む（多人数と同じ列）。命令は、届いた年に実行する。
11. **実行**: もう一度、崩壊・神威を確かめる（足りなければ捨て、理由を返し、聞いている状態を解く）。教えを一覧に加える（同じ教えがあればそれを使う）。神威を払い、歪みを数える。教えの記号のルーンを捨札へ移し、1 枚補う。教えの記号が汚染ルーンならカオス度を上げる。依頼は済む。
12. 予言者の近く（仮 8 タイル以内。地域で数える）の住人が、教えを強度で信じ始める（下の「信仰」）。
13. 行き先があれば、予言者の行き先にする。
14. 方言帳に行を足す（理由: この予言者の言葉／知らない言葉／謎の言葉）。同じ組み合わせの行は 2 度足さない。神託の記録（神の文・聞こえた文・教え・行き先・謎の言葉）を年表に残す。
15. **語り**（LLM 2 回目。結果を待たずに 11〜14 は済ませる）: 神の文・聞き違えの中身・カオス度と調和度を渡し、「聞こえた文」と語りを頼む。検証を通れば、神託の記録に添えて吹き出しに出す。通らなければ、聞き違えを入れた語を並べた規則の文（「〈森〉を〈囲え〉」の形）を聞こえた文にし、語りは今の定型文にする。
16. 吹き出しの頭には、いつも掟の 1 行（「〈火〉を崇めよ」の形。種別ごとのひな形に記号の語を入れる）を出す。
17. 自動進行を「語りかけで止めた」ときだけ、告げた後に再開する。
18. 保存する。
- 予言者が聞いている途中で終了したら、その語りかけは無かったことにする（保存しない）。

### 言葉を選ぶ（LLM が使えないとき・失敗したとき）
1. 名詞の列は、手札の記号の名詞すべて。動詞の列は、全部の動詞。行き先は東・西・なしのボタン。
2. 選んだ名詞・動詞は「知らない言葉」にはならないので、上の 7（ずれ表）から同じ流れに入る。
3. 聞こえた文は規則の文、語りは定型文。

### 信仰（1 年ごと。住人の計算の後）
1. **交流**: その年に「広場に集まる」を選んだ住人どうし（同じ地域）で、信者から信者でない人へ、うつす人の強さ × うつりやすさ（仮）の確率でうつる。うつった強さは、うつす人の強さ × 弱め（仮）。
2. **つがい**: つがいの相手の信仰が、同じ式でうつる。
3. **継ぐ**: 生まれた子は、親（2 人なら強いほう）の信仰を、弱め（仮）を掛けて継ぐ。種別が変わる確率は、この MVP では 0 にしておく（データに置く）。
4. 信じるときは、上限（3）を越えたらいちばん弱いものを捨て、矛盾する教えは弱いほうを捨てる。強さが同じなら、古い教えを残す。
5. 乱数は、住人の ID と年から作る（並べ方で結果が変わらないように）。住人を ID の順に処理する。
6. **忘れられる**: 信者が 0 人になった教えを一覧から消し、年表に「忘れられた」と残す（`event=dogma_forgotten`）。
7. **効き目**: 次の年の `dogmaEffects` と文明の補正に、その教えの「生きている住人のうちの信者の割合」を掛ける。住人がいないときは 0。

### 予言者の旅（1 年ごと）
1. 行き先があれば、その方向の隣の地域へ 1 つ進む。着いた（端に着いた・行き先の地域に着いた）ら行き先を消す。年表に理由つきで残す。
2. 行き先が無ければ、確率 0.1（仮）で、隣の地域のうち「住人の数 − 信者の数」がいちばん多い地域へ移る（同じなら西）。誰もいなければ動かない。
3. 通った地域と、その隣を「知っている土地」に足す（この MVP では使わないが、保存して大きな星で使う）。
4. 予言者の地域は、神託の最初の信者・文明の補正の距離・予言者の絵の場所に使う。

### 祈り
1. 依頼（困りごと）が出たら、手札の記号から 2〜3 個（仮）の名詞を、祈り専用の乱数で選ぶ。新しく手札に入った記号があれば必ず入れる。汚染ルーンが手札にあれば、その語を 1 つ混ぜる。
2. LLM が使えれば、選んだ語だけを渡して祈りの文を頼む（表現だけ。答えは保存し、計算には使わない）。使えないか失敗したら、困りごとごとのひな形に語を入れる。
3. 祈りに出た名詞を、方言帳に「知っている言葉」として足す。
4. 依頼が無い年が続くと、日々の祈りの年（前の祈りから仮 20 年）に、同じやり方で短い祈りをささやく。自動進行は止めない。

### セーブ（版 16）
1. 読み込みで `saveVersion` が 15 以下なら、ファイルを `save.v15.json` に名前を変えて残し（同じ名前があれば上書きしない別の名前）、新しい星で始め、HUD に 1 度だけ知らせる。
2. 足す値: 器の段・ずれ表・方言帳・神託の記録・住人ごとの信仰・予言者の地域と知っている土地と行き先・次の日々の祈りの年・教えごとの ID。どれも読み込みで範囲と一覧を検証し、合わなければ「壊れたセーブ」と同じ扱いにする。
3. プレイヤーの文はセーブにだけ残す。

### 例外とエラー
- LLM の答え・スマホの文は検証していない外部入力。文はファイルのパス・コマンドに使わない。LLM の宛先は今と同じくループバックだけ。
- コアのクラスは、引数が null・範囲外なら `ArgumentException` 系を投げる。データの値が範囲外なら `GameDataLoader` で `InvalidDataException`。
- 不正な `SPEAK` の `Warn` は、今の不正なメッセージと同じく、同じ接続・同じ理由では間引く。

## テスト観点
- ずれ表: 同じシード・同じ器なら同じ表。器が大きいほどずれる語が少ない（多くのシードで比べる）。名詞のずれ先はいつも隣の記号。
- 聞き違え: 知らない言葉が先に当たる・1 か所まで・名詞と動詞の両方が当たるときは動詞・謎の言葉は数えない・名詞が無いと教えを作らない。
- 答えの検証: 一覧に無い ID・隣の外の聞き違え先・長すぎる謎の言葉・壊れた JSON を捨てる。
- 神託の実行: 神威・歪み・ルーン 1 枚の移動・依頼が済む・同じ教えを 2 つ作らない・自動進行の再開。
- 信仰: 上限 3・矛盾・最初の信者は予言者の近くだけ・継ぐ・忘れられて年表に残る・信者 0 なら効かない・割合で効き目が変わる・決定性（同じシード・同じ命令の列で住人ごとの信仰が同じ）。
- 旅: 行き先へ 1 年に 1 地域・端で止まる・広める旅の行き先の選び方・決定性。
- 祈り: 手札の記号の語だけが入る・新しい語が必ず入る・汚染の語・日々の祈りで自動進行を止めない。
- セーブ: 版 16 の読み戻し（表・方言帳・信仰・予言者）・壊れた値・版 15 のファイルを残して新しい星。
- 通信: `SPEAK` の検証（長さ・制御文字・型）・`ORACLE_STATE` の形。
- 手動（Godot・実際の Ollama）: 聞き違えの見え方・吹き出し・方言帳・HUD の信者の数・予言者の絵が動く・LLM を止めたときの「言葉を選ぶ」形・スマホ。

## 仮の値（すべてデータ定義に置き、`TODO(AI_UNSURE)` を付ける）

- 器: 巫 0.3・祭司 0.2・大預言者 0.1。反転の確率（ずれる動詞のうち）0.2。

- 最初の信者: 予言者から 8 タイル以内（4 地域）。交流でうつりやすさ 0.3、つがい 0.5、うつるときの弱め 0.8、継ぐときの弱め 0.8。
- 広める旅の確率 0.1。
