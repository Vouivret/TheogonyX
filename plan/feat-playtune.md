# 遊んで値を決める（MVP の段 4）

## 目的
MVP の核は「字を読み解くこと」と「住人の暮らしを眺めること」の 2 つ。画面の割り付け・色・絵がそろったので、実際に遊んで、仮に置いた値と見た目を直す。
この段は、人間が遊んで感想を出し、AI が値や見た目を 1 つずつ直す形で進める。AI が遊びの中身（ゲームのルール・閾値）を考え出さない。直す値は人間が決めるか、人間の感想から AI が案を出して人間が選ぶ。

## スコープ
- やる:
  - 遊ぶ順の確認項目の一覧（下記）を作る。
  - 値の置き場所の表（下記）を作る。
  - 人間の感想ごとに、値か見た目を直し、直した値を表と仕様書の「未決」に反映する。
- やらない:
  - 新しい機能・新しい規則の追加。感想から新しい規則が要ると分かったら、未決に書いて別の段にする。
  - 手動テスト（`docs/open-items.md` の「人間の手作業」）の合否の記録。遊ぶ中で一緒に確かめてもよいが、記録は人間が行う。

## 遊ぶ順の確認項目
### A 解読（字を読み解く）
1. 祈りの字が出て、手帳に載り、読みの候補を選べる。
2. 神託を出すと、人が字をどう読んだかが分かる（聞き違えを含む）。
3. 字の 3 段階の劣化（`script.decayYears`）が、時代が進むと目に見えて分かる。劣化が速すぎる・遅すぎないか。
4. 刻まれた字（碑・拓本）を押すと拓本が開き、部品が手帳に載る。
5. 禁忌の板（`tabooPlateShare`）が出る頻度。

### B 眺める（水槽）
1. 住人が歩き、家が建ち、つがいが寝て、子が生まれ、墓ができる。1 年の速さ（`timeControl.secondsPerYear`）が眺めるのに合っているか。
2. 人の数（`needs.baseCapacity` ほか）と家の建つ速さが、画面を賑やかにしつつ散らからないか。
3. 昼夜・焚き火・影（`ambience`・`campfire`・`lighting`）の見え方。
4. 新しい絵（住人・建物・予言者）が、ズーム 1〜3 倍で読みやすいか。夜・崩壊のとき（未確認）。
5. 予言者が画面の端の列で見切れること（人間が「カメラは今のまま」と決めた。気になるなら再相談）。

### C 画面
1. 上の帯・下の帯・左の年表・右の手帳・祈りを書く板が重ならないか（1280×720〜1920×1080）。
2. 吹き出しと知らせ（EventTicker）の読みやすさ。

## 値の置き場所
| 感じたこと | 直す値 | 置き場所 |
| :--- | :--- | :--- |
| 字の劣化が速い・遅い | `script.decayYears` | `game/data/rules.json` |
| 聞き違えが多い・少ない | `script.misreadShare` | 同上 |
| 祈りの字数・頻度 | `script.prayerMinWords`・`prayerMaxWords`・`dailyPrayerYears` | 同上 |
| 刻まれる碑の数 | `script.maxStelesPerRegion` | 同上 |
| 時間の進みが速い・遅い | `timeControl.secondsPerYear`・`jumpYears` | 同上 |
| 人が増えない・増えすぎる | `needs.immigrateBelowAdults`・`baseCapacity`・`capacityPerHouse` | 同上 |
| 家が建たない・建ちすぎる | `needs.timberHouseFromTechStage`・`brickHouseFromTechStage`、`civilization.thresholds` | 同上 |
| 飢え・眠りの速さ | `needs.hunger*`・`shelter*` | 同上 |
| 昼夜・焚き火・影 | `ambience`・`campfire`・`lighting` | 同上 |
| ズーム・移動 | `camera.*` | 同上 |
| 信仰の広がり | `belief.*` | 同上 |
| 絵の見た目 | `game/assets/sprites/*.png` | 一時スクリプトで描き直す（リポジトリには入れない）。直したら `-- --quantize-sprites` で合否を確認する |

## 処理の流れ
1. 人間が遊び、感想を出す（言葉でも画面の写真でもよい）。
2. AI が感想を上の表に当てはめ、直す値と案（2 つまで。推奨を先に）を示す。
3. 人間が選ぶ。AI が直し、`sh scripts/check.sh` を通す。
4. 見た目に関わるときは、Godot で動かして画面を確かめる。動かしていないときは、そう報告する。
5. 直した値を、該当する仕様書の「未決」から消し、`docs/open-items.md` と `CHANGELOG.md` を更新する。
6. 複数の感想がたまったら、まとめてコミットする（コミットは頼まれたとき）。

## テスト観点
- 値の変更はデータ定義だけなので、既存のテスト（`sh scripts/check.sh`）が通ることを確かめる。
- 値の下限・上限が `GameDataLoader` の検証に引っかからないこと。
- 期待値を値の変更に合わせて直す場合は、理由を報告に書く。

## 決定事項
- この段の進め方は上の流れ（人間が遊ぶ → AI が案 → 人間が選ぶ）。（2026-11-10）
- 予言者の見切れは、カメラを今のままにする（人間の決定。2026-11-10）。
- 視点は 3 段（星 0.5 倍・街 1 倍・暮らし 2〜4 倍）。切り替えは目盛り単位で、約 0.12 秒のモザイク（ピクセルフォーカス）を挟み、半透明の重ねはしない。群衆の点は星の視点だけ、住人の絵は街と暮らしの視点で出し、暮らしの視点では全住人の頭上に行動の印を出す。（人間の決定。2026-11-11）
- 屋根の切り取り・家の中・音の段階は MVP に入れない（保留）。（2026-11-11）
