# plan: M2 現実同期モード

## 目的
現実の 24 時間でゲーム内の 1 年が進む自動進行の速さを足し、PC に置いて眺め続けるアクアリウムとして遊べるようにする（[ロードマップ](../docs/roadmap.md) の M2 の「現実同期モード」）。仕様は [time-control.md](../docs/domain/time-control.md) と [save-data.md](../docs/domain/save-data.md) に足す。

## スコープ
- 含む
  - 自動進行の速さに「現実同期（24 時間で 1 年）」を足す
  - その年の進み（何秒たったか）と選んだ速さをセーブに残す（`saveVersion` 2）
  - 現実同期で自動進行しているとき、次の年までの残り時間を HUD に出す
- 含まない
  - 閉じていた間の時間を進めること（決定済み。進めない）
  - スマホへの通知（PC のゲームが閉じていると送れない）
  - 昼夜の環境光を現実の時刻に合わせること（今の 12 秒の周期のまま）

## 決定事項
| 決定 | 理由 | ADR化 |
| :--- | :--- | :--- |
| 速さの切り替えボタンは「通常 → 高速 → 現実同期 → 通常」と 3 段で回す | 人間が決めた（2026-10-12） | しない |
| その年の進み（秒）をセーブに残し、起動していた時間を足していって、合計 24 時間で 1 年進む | 人間が決めた（2026-10-12）。途中で閉じても進みが消えない | しない |
| 選んだ速さをセーブに残す。読み込んだ後は止まった状態で始まり、自動進行を押すとその速さで進む | 人間が決めた（2026-10-12） | しない |
| 現実同期で自動進行しているとき、HUD に「次の年まで hh:mm:ss」を出す | 人間が決めた（2026-10-12） | しない |
| 処理の流れと、下の AI の案を、この plan のとおりにする | 人間が承認した（2026-10-12） | しない |
| **AI の案**: 自動進行の時計を、Godot の `Timer` から、コアの新しいクラス `AutoPlayClock`（速さ・その年の進み）に替える。`WorldScreen` が `_Process` の `delta` を渡す | 進みを保存・復元するには、経過した秒を自分で持つ必要がある。テストできる | しない |
| **AI の案**: 一時停止しても、その年の進みは残す（再開すると続きから数える）。速さを切り替えたとき・世界再創生のときは 0 に戻す | 一時停止は今の `Timer` では進みを捨てていたが、現実同期で神託のたびに数時間分が消えるのを避ける。速さの切り替えで数え直すのは今と同じ | しない |
| **AI の案**: 1 フレームで進めるのは 1 年まで。フレームが遅れて 2 年分たまったら、次のフレームで次の年を進める | 今の `Timer` も 1 フレームに 1 回しか鳴らない。夢・依頼で自動進行が止まる判断を、1 年ごとに行える | しない |
| **AI の案**: 自動進行中の定期的な保存を「5 分たった後の、次の 1 年が進んだとき」から「自動進行中、5 分ごと」に変える | 現実同期では 1 年が 24 時間なので、年が進むのを待つと、その年の進みが保存されない | しない |
| **AI の案**: 現実同期の 1 年の秒数（86400）は `game/data/rules.json` の `timeControl.realTimeSecondsPerYear` に置く | 調整値を直書きしない | しない |

## セーブデータの形の変更（`saveVersion` 1 → 2）
- 足す項目: `"autoPlay": { "speed": "NORMAL" | "FAST" | "REAL_TIME", "elapsedSeconds": 0 以上の有限の数 }`
- `saveVersion` 1 のセーブは読まない（壊れたセーブと同じく、別の名前で残して新しい星で始める）。配布前（Phase 1）なので変換は作らない（`save-data.md` のルール）。

## 処理の流れ

### 自動進行（`WorldScreen._Process` から毎フレーム）
- 状態が自動進行中でなければ、何もしない（その年の進みはそのまま）。
- `AutoPlayClock.Tick(delta)`: 進みに `delta` を足す。進みが今の速さの 1 年の秒数以上なら、1 年の秒数を引いて「1 年たった」を返す。`delta` が負・有限でないときは例外。
- 「1 年たった」なら、今と同じく `TimeControl.AdvanceOneYear` → 夢・依頼の判定 → 画面の更新。
- 現実同期で自動進行中なら、HUD の残り時間（1 年の秒数 − 進み）を、表示する秒が変わったときだけ書き換える。それ以外のときは隠す。

### 速さの切り替え（ボタン）
- 通常 → 高速 → 現実同期 → 通常 と回す。どの状態でも押せる（今と同じ）。
- 進みを 0 にする。

### 世界再創生
- 今の処理に加えて、進みを 0 にする。速さはそのまま。

### 保存と読み込み
- 保存: 今の項目に加えて、速さと進みを書く。
- 読み込み: `saveVersion` が 2 でなければ失敗（`unsupported_save_version`）。速さが知らない値、進みが負・有限でない・項目が無いなら失敗。成功したら、速さと進みを `AutoPlayClock` に戻す（状態は止まったまま）。
- 自動進行中は、前の保存から 5 分（現実の時間）ごとに保存する（`_Process` で数える）。神託・100 年跳躍・世界再創生の後と、終了時は今と同じ。

## テスト観点
- 自動（コア）: `AutoPlayClock` が速さごとの秒数で 1 年を返す、1 回の `Tick` で 1 年まで、速さの切り替えで進みが 0 になる、不正な `delta`。セーブの読み戻しで速さと進みが戻る、`saveVersion` 1 と不正な `autoPlay` を読まない。
- 手動: 現実同期にして残り時間が減っていくこと、閉じて起動して自動進行を押すと残り時間が続きから減ること、速さのボタンが 3 段で回ること。
- 受け入れ条件は AC-time-control-009〜013、AC-save-data-010・011。テスト仕様書は TS-time-control-010・011、TS-save-data-006。
