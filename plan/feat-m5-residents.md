# plan: M5 住人（人の欲求と健康の最初の範囲）

## 目的
群衆とは別の少数の「住人」が、1 年ごとに欲求で暮らし、飢えと恐怖で崩れ、死ぬまでを作る（[agent-needs.md](../docs/domain/agent-needs.md) の「M5 で作る最初の範囲と値」、[ロードマップ](../docs/roadmap.md) の M5 の最初）。神のドグマ（環境・カオス度）が人の体と心に届き、狂乱が建物を壊してカオス度を上げる、という形でコアループに人の層を足す。

## スコープ
- 含む
  - コア: 住人のモデル（欲求・体力・SAN 値・精神の状態・名前・称号）、1 年ごとの計算、墓、世界再創生での消去
  - データ: `game/data/rules.json` の `needs`（仮の値）と、名前のパーツ・称号の ID
  - セーブ: 住人・墓・次の住人の ID を足し、`saveVersion` を 5 に上げる（[save-data.md](../docs/domain/save-data.md) に受け入れ条件を足す）
  - 画面: 仮の色の人形（16 px ほど）、1 日の暮らし（昼は地域の中を歩く・夜は建物のそばで眠る）、クリックで情報の欄、墓
  - 文言: 名前のパーツ・称号・タスク・情報の欄の表記（`game/locales/ui.csv`）
  - 用語集に 住人・欲求・SAN 値・精神崩壊・称号・家名 を足す
  - ログのキー `residentId`・`region`・`name`・`breakdown` を `project.md` 7 章の表に足す文面を提案する（ルールファイルは人間が足す。`project.md` 8 章）
- 含まない
  - つがいと世代交代・異端の教祖・変異・負傷と疾患・歴史の記録（仕様書で後に回した）
  - 住人の絵（アセット）。仮の色の人形
  - スマホへの住人の表示（通信の契約は変えない）
  - 群衆の変更（GPU 版と CPU 版の突き合わせは変えない）

| 住人は仮の色の人形で見せ、クリックで名前・欲求・体力・SAN 値を出す | 人間が決めた（2026-10-13） | しない |

| **AI の案**: 住人の計算は `ResidentSimulator.AdvanceYear` として、`TimeControl` の毎年の計算（`afterYear`）の中で、文明の計算（`CivilizationSimulator.AdvanceYear`）の直後に呼ぶ。住人の一覧は `Civilization` とは別の `Residents` クラスに持たせる | 仕様書の「地層の計算の後」。`WorldSimulator` は崩壊した年に `afterYear` を呼ばないので、「崩壊した年には計算しない」がそのまま満たせる。建物と住人を別にすると、`Civilization` のテストの期待値を変えずに済む | しない |

| **AI の案**: ドグマの強度（`float`）は `float` のまま、データの閾値も `float` にして比べる | 強度 0.8 のドグマが、型の違いで閾値を割らないようにする（AC-agent-needs-018） | しない |

## 処理の流れ

### データの読み込み（`GameDataLoader`）
- `needs` を読み、`NeedsRules` を作る（仕様書の値の表のすべての値と、名前のパーツの ID の並び・称号の ID）。
- 次のときは読み込みを失敗にする（`InvalidDataException`）: 項目が無い、欲求の値が 0〜1 の外、体力・SAN 値が 0〜100 の外、確率の和が 1 でない、年数が負、名前のパーツが空・重複。

### 1 年の計算（`ResidentSimulator.AdvanceYear`。崩壊していない年だけ）
1. **移り住む**: 地域の番号の小さい順に、住人の数が「2 ＋ 建物の数 × 4」より少なければ 1 人足す（ID は次の番号、生まれた年 = 年 − 20、体力・SAN 値 100、交流・承認・自己実現 0.0、正常、称号無し）。名前は「シード × ID」のハッシュから作った別の乱数で、名・家名のパーツを選ぶ。
2. **欲求を動かす**（全員）:
   - 飢饉 = 森林量 ≤ 30 または 水資源 ≤ 30。空腹 = 自閉・絶望なら 1.0、飢饉なら 0.9、それ以外は 0.1。
   - 住居 = 地域に建物があり、地域の住人の数 ≤ 建物の数 × 4 なら 0.1、そうでなければ 0.8。
   - 交流 ＋0.2・承認 ＋0.1・自己実現 ＋0.05（1.0 で止める）。
3. **体力・SAN 値・死**:
   - 上限 = 年齢が 50 以上なら 100 − 2 ×（年齢 − 50）、それ以外は 100（0 で止める）。
   - 体力 = 飢饉か自閉・絶望なら 体力 − 20、それ以外は 体力 ＋ 10。上限と 0 で止める。
   - SAN 値 −= カオス度 ÷ 10。空腹・住居がどちらも 0.6 未満なら ＋5。0〜100 で止める。
   - 体力 0 の住人を死なせる（状態遷移表で「死」）。一覧から外し、墓を足し、`resident_died` を出す。
   - 地域ごとに、その年に死んだ人数 × 10 を、残った住人の SAN 値から引く（0 で止める）。
4. **精神崩壊と戻り**（地域の中は ID の小さい順。乱数は「シード・年・地域」から作る）:
   - 崩壊中で、崩壊した年から 3 年たった住人は正常に戻し、SAN 値を 30 にする。
   - 正常で SAN 値 0 の住人は、乱数で狂乱か自閉・絶望にする（崩壊した年を残す）。`resident_breakdown` を出す。
   - 崩壊中で SAN 値 0 の住人には何もしない（表で「不可」の遷移を起こさない）。
5. **称号**（称号の無い住人だけ）: その年に狂乱になった → `EPITHET_BLOODLESS`。21 歳になった年に、星全体のドグマの一覧に強度 0.8 以上のものがある（予言者からの距離による効き目は掛けない）→ いちばん強いドグマ（同じなら先にできたもの）の記号で `EPITHET_WITNESS`。81 歳になった年 → `EPITHET_ELDER`。1 人が同じ年に 2 つ満たしたら、この順で最初のものにする。
6. **タスク**:
   - 崩壊中 → 崩壊の行動（狂乱なら、崩壊したその年だけ、カオス度 ＋5 と、地域に建物があれば乱数で 1 つを `Civilization.Collapse`）。
   - 空腹・住居のどちらかが 0.6 以上 → 高いほう（同じなら空腹）のタスク。欲求は減らさない。
   - 交流 ≥ 0.6・承認 ≥ 0.6（地域に祠がある）・自己実現 ≥ 0.5（地域に工房がある）のうち、いちばん高いもの（同じなら下の段階）のタスクにし、その欲求を 0.5 減らす（0.0 で止める）。
   - どれでもなければ何もしない。
7. **墓**: 死んだ年 ＋ 10 ≤ 年 の墓を消す。

### 世界再創生（`TimeControl.Reset`）
- 住人と墓をすべて消し、次の住人の ID だけを残す。

### セーブとロード
- 住人（ID・地域・生まれた年・5 つの欲求・体力・SAN 値・精神の状態・崩壊した年・その年のタスク・名と家名のパーツ・称号と証人の記号）、墓、次の住人の ID を書く。`saveVersion` は 5。
- 読み込みでは、項目が無い・型が違う・値が範囲の外・定義に無いパーツ・称号・記号・同じ ID が 2 回・地域が 16 の外 を失敗にする（今の読み込みと同じく、読めず理由が分かる）。

### 画面（`ResidentView`。Y ソートのレイヤーに置く）
- 年が進んだとき・ロード・世界再創生で、住人と墓の一覧を描き直す。
- 住人ごとに、地域の中で、昼はその年のタスクの建物（無ければ地域の中のマス）へ歩き、夜は地域の建物のそば（無ければその場）で横になる。時刻は今の昼夜の周期（`AmbientLight`）に合わせる。
- 地上の表示のときだけ描く（地層の地下の表示では隠す）。
- クリックした住人の欄に、名前・欲求・体力・SAN 値を出す。住人が死んだら欄を閉じる。
- 墓は仮の色の小さな四角で、死んだ地域の中に置く。

## テスト観点
- 自動（コア）: TS-agent-needs-001〜010（[docs/test/agent-needs.md](../docs/test/agent-needs.md)）。狂乱で廃墟になった枠に、その年ではなく次の年の文明の計算で建て直されること（AC-agent-needs-012）を含む。データの検証。セーブの往復と壊れたセーブ（[save-data](../docs/test/save-data.md) に足す）。
- 既存のテスト: 住人の計算を足しても、文明・地層・環境のテストの期待値は変えない（住人のいない設定で確かめる）。`saveVersion` 4 のセーブを読めないことを確かめるテストは、5 への追従として期待値を変える（機械的な追従。報告に書く）。
- 手動: TS-agent-needs-011。
- 性能: 1000 年の跳躍の時間を、住人ありと無しで測って報告する（[nfr.md](../docs/nfr.md)）。
