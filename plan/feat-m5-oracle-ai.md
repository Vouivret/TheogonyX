# plan: 予言者の誤解（ローカルの LLM による神託の文）

- 仕様書: [docs/domain/ai-presentation.md](../docs/domain/ai-presentation.md) の「予言者の誤解」・AC-ai-presentation-001〜006
- テスト仕様書: [docs/test/ai-presentation.md](../docs/test/ai-presentation.md)

## 目的
神託でドグマが生まれたとき、予言者が神の意図を誤解して語る文を、ローカルの LLM で毎回違う言葉で見せる。AI による表現の最初の仕組み。

## 決定事項（2026-10-13、人間が決めた）
- モデルは Ollama の `gemma2:9b`（データで変えられる）。
- 文は予言者の吹き出しに出し、年表のドグマの行に添えてセーブに残す（`saveVersion` 9）。
- LLM が使えないときは、種別ごとの定型文を出す（年表には残さない）。
- 予言者の心の状態は、カオス度と調和度だけを渡す。
- 待つ秒数 60・吹き出しの秒数 20・文字数の上限（見出し 30・ほか 80）は AI の仮置き。

## 処理の流れ
1. 神託を下してドグマが生まれたら（`DreamView.OraclePronounced`）、年表の最後の行（そのドグマの行）と一緒に頼みを積み、吹き出しに「紡いでいる…」を出す。使わない設定なら定型文を出して終わる。
2. 頼みは一度に 1 つずつ、Godot 側の `HttpClient` で Ollama の生成 API に送る（コアの `OracleProphecy.BuildRequest`）。
3. 応答をコアの `OracleProphecy.ParseResponse` で検証する。通れば年表の行に添えて（`History.AttachOracle`）セーブし直す。いちばん新しい神託なら吹き出しに 20 秒出す。
4. つながらない・時間切れ・HTTP のエラー・形の崩れは、`event=oracle_ai_failed` を `Warn` で出し、いちばん新しい神託なら定型文を出す。
5. セーブは年表のドグマの行に `oracle` を足し、読み込みで同じ検証をする。

## テスト観点
- 頼みの文と本文の形・応答の検証・宛先がループバックだけ・年表に添えること・セーブの読み戻しと壊れた文（自動。LLM は呼ばない）。
- 実際の Ollama での見た目と、止めたときの定型文（手動）。

## 実装の記録
- 頼みの文を curl で `gemma2:9b` に送ると、3 秒ほどで形の合った文が返った。ほかのアプリが Ollama で別のモデル（12 GB）を同時に使っていたときは、モデルの読み込み直しで 54〜120 秒かかり、時間切れが出た。
- 1 回、Ollama が `token repeat limit reached` のエラーを返した。HTTP のエラーとして定型文に戻る。
- 意図の文に「予言者は…と誤解した」と種明かしが入ることがあったので、頼みの文に「誤解には触れず、予言者自身の言葉で語れ」を足した。
