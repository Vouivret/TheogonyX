# 運用手順

> 配布（体験版を含む）の前までに、空欄を埋める。

## ビルドの種類
| 種類 | 用途 | 書き出し先 | 作るタイミング |
| :--- | :--- | :--- | :--- |
| 開発 | 開発中の動作確認（デバッグ情報あり） | エディタから実行 | 随時 |
| リリース候補 | 配布前の通しプレイ確認 | `export/` | リリース候補の作成時 |
| 配布 | プレイヤー向け | 配布先: 未定 | リリース時 |

環境ごとに違う設定値（コンパニオンの待ち受けポートなど）は、コードに書かず設定ファイルで渡す。

## コンパニオンとの通信
- ポートは `game/data/companion.json`（HTTP 8080、WebSocket 8081）。WebSocket のポートを変えたら、`companion/js/protocol.js` の `WEBSOCKET_PORT` も同じ値にする。
- 初めて起動したとき、Windows ファイアウォールの許可を求められる。「プライベート ネットワーク」だけを許可する。
- 書き出した後は、実行ファイル（.exe）と同じフォルダに `companion/` を丸ごとコピーする。無いと、コンパニオンは使えない（ゲームは動く）。

## リリース
1. `CHANGELOG.md` の `Unreleased` を確認し、Semantic Versioning でバージョン番号を決める。
   - セーブデータの互換性を壊す変更あり → メジャー
   - 機能追加あり → マイナー
   - 不具合修正のみ → パッチ
2. `project.godot` の `config/version` を更新する。
3. 

## 書き出しと配布
1. Godot のエクスポート（プリセット: 未定）で `export/` に書き出す。
2. リポジトリ直下の `companion/` を、書き出した実行ファイルと同じフォルダにコピーする。
3.

## 重大な不具合への対応
1. **検知**: セーブデータの破損・起動しない・進行不能を最優先で扱う。
2. **影響の確認**: 影響するバージョン・環境・セーブデータを確認する。
3. **暫定対応**: 原因の調査より先に、1つ前のバージョンへのロールバックや告知で影響を止める。
4. **連絡**: プレイヤーへの告知の要否を判断する。
5. **収束後**: `docs/postmortem/_template.md` をコピーして振り返りを書く。
