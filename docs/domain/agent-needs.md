## 目的

人が自分の欲求に従って暮らし、満たされれば崇められたい・真理を知りたいと上を目指し、飢えや災害では生き延びることだけに走る様子を見せる。神（プレイヤー）のドグマが人の体と心を変え、そこから予想できないドラマ（狂乱・絶望・異端の教祖）が生まれるようにする。

## ゲームのルール

用語は [用語集](glossary.md) に合わせる。指示書の内容を写したもので、数値・条件の多くは「未決」にある。

### 決定性の境界
- 欲求・健康・タスクの選択・精神崩壊・変異は、すべてコアがシードを指定した乱数（`System.Random`）で決める。同じシード・同じ入力からは同じ結果になる。
- 人の ID は通し番号で振る（`Guid.NewGuid()` は実行ごとに変わり、決定性が壊れる）。座標はコアで定義した型を使い、Godot の型（`Vector2` など）を使わない。
- AI（LLM・画像生成）は、コアが決めた結果を語る・描くだけにする（[AI による表現](ai-presentation.md)と同じ）。
- 同じシードで、欲求のたまり方・精神崩壊が起きる時・選ぶタスクが毎回同じになることを、自動テストで保証する。

### 欲求の 5 段階
- 人は 6 つの欲求を持つ。値は 0.0（満たされている）〜 1.0（切実）で、時間とともに増え、行動で減る。

  | 段階 | 欲求 | 満たす行動の例 |
  | :--- | :--- | :--- |
  | L1 生理的欲求 | 空腹（`NeedHunger`）・睡眠（`NeedSleep`） | 食事、眠る、体温を保つ（焚き火・水） |
  | L2 安全の欲求 | 住居（`NeedShelter`） | 屋根のある家、災害・野獣から逃げる、医療 |
  | L3 社会的欲求 | 交流（`NeedSocial`） | 仲間との会話、集会・祭り、つがい |
  | L4 承認・尊厳 | 承認（`NeedEsteem`） | 暗黒議会の議員になる、装飾品・立派な家、地位 |
  | L5 自己実現 | 自己実現（`NeedActualization`） | 新しいドグマを唱える、独自の巨大建築・碑文、芸術・極秘研究、異教の儀式 |

- 下の段階の欲求が満たされていないと、上の段階の欲求からはタスクを選ばない（L1・L2 が閾値より下のときだけ、L3〜L5 を評価する）。
  - 平常時: 腹が満ち、家がある → 崇められたい（L4）→ 真理を知りたい（L5）→ 勝手に新しいドグマを唱え始める。
  - 飢え・災害のとき: L3〜L5 をすべて止め、食料の奪い合いと避難（L1・L2）だけをする。

### タスクの選び方
- 人は、次の順にタスクを選ぶ。
  1. 精神崩壊中なら、崩壊の行動（狂乱 → まわりを壊す、自閉・絶望 → 何もしない）。
  2. 下の段階から順に、閾値を越えた欲求のタスク（空腹 → 食料を探す、睡眠 → 眠る、住居 → 家を建てる）。
  3. L1・L2 が満たされていれば、交流 → 広場に集まる、承認 → 装飾品を作る、自己実現 → 新しいドグマを唱える。
  4. どれでもなければ、何もしない（`Idle`）。
- 選んだタスクの目的のマス（食料・祭壇・広場など）へ移動する。

### 肉体の健康
- 体力（`Health`、0〜100）は、空腹・極寒・負傷・老衰で減る。0 になると死に、そのマスに墓（死体）を置く。
- 状態異常:
  - 負傷: 移動が遅くなる。手当て（医療）をしないと感染症になる。
  - 疾患・聖病: 自然に起きる病気のほか、ドグマ（赤き雨など）で体がヒレ・エラに変わっていく（海底人への変異の途中）。体力が減る代わりに、変異が進む。
  - 老衰: 年を取るにつれて、体力の上限が下がる。

### 精神の健康（SAN 値）
- SAN 値（`Sanity`、0〜100）は、仲間の死・恐怖のドグマ・カオス度の上昇で減る。
- SAN 値が 0 になると、シードを指定した乱数で次のどれかの精神崩壊になる。
  - 狂乱（`Rampage`）: まわりの建物・人を壊す（カオス度が上がる）。
  - 自閉・絶望（`Catatonia`）: 食事を拒み、神への呪いの言葉をつぶやき続ける。
  - 異端の教祖（`CultLeader`）: 自分で作ったドグマをまわりに感染させ、カルトを作る。

### つがいと世代交代
- 人は、繁殖の欲求（`NeedLibido`）と愛着の欲求（`NeedAffection`）を持つ（0.0〜1.0）。L1・L2 の欲求が満たされているとき、時間とともに増える。
- 求愛・つがい・子供をもうけることができるのは、大人の年齢以上の人だけとする（2026-10-13 に決定。年齢は「未決」）。
- 流れ（どれもコアがシードを指定した乱数で決める）:
  1. 求愛: 欲求が高まると、近くでいちばん好感度の高い相手のところへ行き、求愛する。
  2. つがい: 双方が同意すると、パートナーになり、同じ家（住居）に住む。
  3. 世代交代: つがいから、一定の確率で子供が生まれる。親の性質（ドグマへのなじみやすさ・種族の変異）が子供に引き継がれる。
- 人どうしの関係: 独身・交際中・夫婦・敵。好感度は −1.0〜1.0。
- 恋愛のもつれ: 求愛を断られる・パートナーを奪われる・好感度が急に下がると、SAN 値が大きく減る。SAN 値が 0 になったときの精神崩壊に、恋がもとの形（心中、恋敵やパートナーへの襲撃）が加わる。
- ドグマとの関わり（指示書の例）:
  - 「快楽・愛の崇拝」: 繁殖の欲求が減りにくくなり、街じゅうが愛を語らう楽園になる。人口が増えすぎて食料が足りなくなる。
  - 「禁欲・純潔」: 欲求を抑えられた人の SAN 値が少しずつ減り続け、裏で秘密のクラブができるか、人口が減って文明が衰える。
- 異なる種族の間の子供: 陸の人と海底人の子供は、両方の環境に適応した半魚人になる。陸でも海でも暮らせるが、どちらの種族からも異端として扱われる。
- 画面では、愛の営みを象徴的な表現（同じ家に入る、ハートのアイコンなど）にとどめる（2026-10-13 に決定）。

### 名前と称号
- 人は、生まれたときに名前を持つ。名前は「名（First Name）・家名（Lineage）の 称号（Epithet）」の 3 つの部分でできている。
  - 例: 「アルトリウス・イリアス の 柱を築く者」、「ギル・ルルイエ の 深海の狂信者」（海底人）
- 名と家名は、種族と地域の文化の値に応じて、音のパーツ（接頭辞 ＋ 接尾辞）を組み合わせて作る。組み合わせはコアがシードから決める。
  - 陸の人（古典神話・英雄伝風）: 接頭辞 アルト-・ヴァル-・イリオ-・エル-・セレ-・オル-、接尾辞 -トリウス・-ウス・-フィア・-ギス・-ミオン・-ア
  - 海底人・深海の種族（異形の神話・深海風）: 接頭辞 ギル-・ダゴ-・ルル-・ゾス-・クル-・ヴォル-、接尾辞 -イエ・-アシュ・-トル・-グア・-イン
- 名前を作る乱数は、シミュレーションの乱数と分ける案にする（2026-10-13）。「シード × 人の通し番号」から作る別の乱数（群衆の `CrowdHash` と同じ考え方）にすれば、名前を足しても、戦争や建物などほかの結果は変わらない。
- 子供は、親の家名を引き継ぐ（どちらの親かは「未決」）。
- 称号は、行いで得る（指示書の例）。

  | きっかけ | 称号の例 |
  | :--- | :--- |
  | 建物をいくつも建てた | 街を包む者 |
  | 精神崩壊（狂乱など）を起こした | 血を恐れぬ者 |
  | 強いドグマを信じている | 赤き雨の証人 |
  | 戦争で敵の地域を壊した・占領した | 廃墟の征服者 |
  | 老衰 | （指示書に例が無い） |

- 人が死ぬと、名前と称号を歴史の記録（`HistoryLog`）に残す。地下の地層にも残し、発掘したときに読めるようにする（[地層](strata.md)の未決）。
- 名前と称号は表現で、ゲームの計算には関わらない。

## 未決

### 指示書の中での食い違い
- **上の段階に進める条件**: 文章は「L1・L2 が 0.6 未満のときだけ L3〜L5 を評価する」。コード例は「空腹が 0.8 を越えたら食事」で、空腹 0.7 でも集会（L3）に行ける。どちらに合わせるか。
- **異端の教祖の行動**: 精神崩壊の 3 種類のうち、`CultLeader` のタスクがコード例に無い。

### 前提になる仕組み
- **時間の細かさ**: タスクは 1 日ごとに選ぶ形（`EvaluateDailyTask`）だが、今の計算の 1 回（Tick）は 1 年（[文明の創発的な発展](emergent-progression.md)の「1 年ごとの計算」）。1 年より細かい Tick をどう作るか（ロードマップの構想「1年より細かい時間の流れ」）。
- **群衆との関係**: 今の群衆（10,000 人の点）は見た目だけで、結果に影響しない（[群衆](crowd.md)）。狂乱でカオス度が上がる・建物が壊れる・墓が残ると、人が結果を変える。群衆を結果に影響させるか、別に少数の人を足すか。GPU 版と CPU 版の突き合わせをどうするか。
- **移動の方式**: 目的のマスへの移動と障害物の回避に、今のポテンシャルフィールドを使うか。
- **先に要る構想**: 住居・広場・祭壇・食料（[文明の創発的な発展](emergent-progression.md)の建物）、繁殖・老衰・死（ロードマップの構想「世代交代と教義の変質」）、海底人への変異（構想「異人種と海中都市」）、野獣・災害（ロードマップの「イベント」と、文明の発展の「カオス度によるイベント」）。
- **人が唱えるドグマ**: 今のドグマは、プレイヤーが予言者の夢を改ざんしたときだけ生まれる（コアループ）。人が新しいドグマを唱える・感染させると、コアループが変わる。生まれるドグマ（記号と種別）の決め方、暗黒議会・世代交代との関係。

### つがいと世代交代
- **欲求が増える条件の閾値**: 繁殖・愛着の欲求が増えるのは「L1・L2 が 0.4 以下」のとき、L3 以上を評価するのは 0.6 未満（上の「上の段階に進める条件」）、タスクを選ぶのは 0.7 と、閾値が 3 つある。また、繁殖の欲求はマズローの L1（生理的欲求）、愛着は L3（社会的欲求）にあたるが、指示書ではどちらも L1・L2 が満たされたときだけ増える。どの段階に置くか。
- **精神崩壊の種類**: 「心中」は相手を死なせるので、自閉・絶望（`Catatonia`、何もしない）とは違う行動になる。指示書の `JealousRampage` を新しい種類として足すか、狂乱（`Rampage`）の対象が恋敵・パートナーになるだけにするか。
- **ドグマへのなじみやすさ**: 指示書の「ドグマ順応度」はどこにも定義が無い。技術（`TechVector`）は地域ごとの値で、人ごとの値ではない。人ごとに何を持たせ、どう引き継ぐか。
- **好感度の表の大きさ**: 人ごとに全員への好感度（指示書の `AttractionMap`）を持つと、10,000 人で 1 億件になる。近くの数人だけにするなどの上限。
- **ドグマの形**: 今のドグマは「記号 × 種別（禁忌・崇拝・破壊）」。「愛」の記号を足せば、愛の崇拝 → 快楽の楽園、愛の禁忌 → 禁欲・純潔 と当てはまる。[文明の創発的な発展](emergent-progression.md)の未決「記号を足すか」と一緒に決める。
- **先に要るもの**: 食料のモデル（人口が増えすぎて食料が足りなくなる）、住居（同居）、年齢と死（ロードマップの構想「世代交代と教義の変質」）、半魚人（構想「異人種と海中都市」）。
- **大人の年齢**と、子供が生まれる確率・人口の上限。
- **年齢区分**: 恋愛・繁殖の表現の度合いが、配布するときの年齢区分（IARC・CERO など）にどう影響するか。

### 名前と称号
- **言語ごとの表示**: 文言は翻訳ファイルに置く（`.agent/rules/ui.md`）。称号は、コアが称号の ID（例: `EPITHET_CONQUEROR`）だけを持ち、表示するときに翻訳する案。名前の音のパーツは英語版で別の表記（Art-・-orius など）が要るので、パーツの ID を持って表示のときに組み立てるか、名前は日本語だけにするか。「X の Y」の語順（英語では「X the Y」など）を翻訳ファイルで決めるか。
- **組み合わせの少なさ**: 陸の人は接頭辞 6 × 接尾辞 6 = 36 通りで、10,000 人では同じ名前だらけになる。家名と合わせても重なる。パーツを増やすか、重なりを許すか。
- **文化の値の効き方**: 「地域の文化の値に応じて」音を組み合わせるとあるが、どう効くかが無い。
- **家名の引き継ぎ**: 父母のどちらの家名か、異なる種族の間の子供（半魚人）の名前と家名のパーツ。
- **称号の条件**: 「いくつも」の数、「強いドグマ」の強度の閾値、老衰の称号。称号は 1 つだけか（上書きするか、最初のものを残すか）、いくつも持てるか。『赤き雨の証人』のように、ドグマの記号の名前を差し込む形にするか。
- **歴史の記録**: `HistoryLog` は新しい仕組み。何を残し、どこに見せるか（[AI による表現](ai-presentation.md)の「歴史の神話化」と一緒に決める）。セーブの形が変わる。

### 規則と値
- 欲求の増える速さと、行動で減る量。タスクを選ぶ閾値（指示書の例: 空腹・睡眠 0.8、住居 0.7、交流・承認 0.6、自己実現 0.5）。初期値（指示書の例: 体力 100・SAN 値 100・20 歳）。これらはゲームデータ定義（`rules.json`）に置く。
- 体力・SAN 値の減り方、負傷・感染症・疾患・老衰の条件と量。
- 精神崩壊の 3 種類の確率と、崩壊から戻るか。狂乱で上がるカオス度の量。
- 変異が進む条件と、変異が終わったときの扱い。

### 性能
- 人数と、CPU で欲求 6 つ・体力・SAN 値・状態異常を細かい Tick で計算したときに、[nfr.md](../nfr.md) の性能の目標を満たすか。
