# 仕様書: AI による表現（LLM・画像生成）

- テスト仕様書: [docs/test/ai-presentation.md](../test/ai-presentation.md)（予言者の誤解の分）
- 関連ADR: なし
- 通信: なし（ローカルの Ollama の生成 API だけ。下の「予言者の誤解」）
- 画面デザイン: なし
- 出典: `memo/add_llm.md` と、2026-10-12 のチャットでの確定方針・追加の指示書（32×32px のアセット生成）
- 着手: [ロードマップ](../roadmap.md)の M3 の後（M4 の構想）

## 目的

ローカルで動く LLM（Ollama など）と画像生成（ComfyUI）を使い、予言者の神託・人々の会話・歴史・カードや地表のドット絵を、遊ぶたびに違う言葉と絵で見せる。神の意図が人間に誤解されていく様子を、数値ではなく物語として眺められるようにする。

## ゲームのルール

用語は [用語集](glossary.md) に合わせる。

### 決定性の境界
- ゲームの計算はすべてコアが行い、同じシード・同じ入力からは同じ結果になる。環境の数値・カオス度の変化、イベントの ID の選択、崩壊の判定は AI に任せない。
- AI は、コアが決めた結果（数値・イベントの ID・`DogmaType`）を受け取り、表現（フレーバーテキスト・神託・会話・32×32px のドット絵）だけを非同期（`async`/`await`）に作る。AI の出力がどう変わっても、ゲームの計算は変わらない。
- 作った表現をもう一度見せたいときは、生成した結果をセーブに残し、読み込んだときにそれを使う。

### AI に渡すもの
- 新しいカードのクラスは作らない。入力は、夢の改ざんから生まれた既存のドグマ（`DogmaType` × `Intensity`）である。画面でカード風に見せるときも、中身は既存のドグマを指す。
- 予言者の心の状態には、新しい状態を作らず、既存のカオス度（`ChaosLevel`）と調和度（`HarmonyLevel`）を使う。

### AI の応答の検証
- AI の応答は、コンパニオンからのメッセージと同じく、検証していない外部入力として扱う。
- 応答の形（スキーマ）を検証する。イベントの ID などは、前もって決めた一覧（ホワイトリスト）と照らし合わせる。
- 一覧に無い ID や形の崩れた応答は使わず、安全な既定の演出に戻す。

### 通信
- AI のサービスとは、ローカルループバック（127.0.0.1）だけで通信する。ComfyUI は `http://127.0.0.1:8188` の API を使う。
- [AI_USAGE_POLICY.md](../AI_USAGE_POLICY.md) に従う。

### ドット絵のアセットの生成
- 規格: 32×32px、DB16（Dawnbringer 16）のパレットに減色、背景を透過した PNG。
- 流れ:
  1. ゲームから ComfyUI の API にプロンプトとワークフローを送る。
  2. ComfyUI の中で、SD1.5 か SDXL で生成し、32×32px に縮め、DB16 のパレットに当てはめ、背景を透過する。
  3. ゲームは画像を受け取り、テクスチャにして地表のオブジェクトやカードの背景に割り当てる。
- 生成中と失敗したときは、既定の絵（プレースホルダー）を出す。生成を待ってゲームの進行を止めない。
- 生成のきっかけは、改ざんで生まれた新しいドグマや、環境の変化である。

### 5 つの仕組み（概要）

| 仕組み | コアが決めること | AI が作るもの |
| :--- | :--- | :--- |
| 予言者の誤解 | カオス度と、ドグマ（`DogmaType` × `Intensity`）による数値の変化 | 神の意図を誤解した不吉な神託の文（見出し・誤解した意図・歪んだ教義） |
| 暗黒議会 | 100 年ごとの節目に選ぶイベントの ID と、その効果（一覧にある ID だけ） | 教祖・軍事指導者・科学者の 3 人の議論の記録 |
| 歴史の神話化 | 100 年ごとの確定した記録（年・`DogmaType`・カオス度の変化） | 記録の要約と、時代が進むほど細部が欠けて神話に変わった文（スマホの「創世図鑑」に残す） |
| 聖遺物 LoRA | 周回の終わり（1000 年完走か星の崩壊）に、影響の大きかった `DogmaType` の組み合わせの記録 | 次の周回の画像生成と AI の語り口に渡すパラメータ。前の周回の歴史が、次の周回の画風と語り口に染み出す |
| ドット絵の動的生成 | 上の 4 つの展開と、置く場所 | 地表に置く未知の神聖なオブジェクト・怪異の 32×32px のドット絵 |

### 着手の時期（2026-10-13 に決定）
- M4 ではやらず、M5 以降に回す。理由:
  - 5 つの仕組みのうち 4 つは、まだ無い仕組みを前提にしている（暗黒議会のイベントの ID、歴史の記録、周回の終わり、発掘と二次誤解）。先に作ると、AI に渡す入力が後で変わる。
  - ローカルの LLM・ComfyUI のインストールと、モデル・カスタムノードのライセンスの確認が要る（`.agent/rules/project.md` の 5.2）。外部から受け取る値の検証と既定の演出も要り、Phase 1 の重点（コアループとモデルの整合性）から外れる。
- 着手するときは、前提が今そろっている「予言者の誤解」（ドグマの `DogmaType` × `Intensity` とカオス度から、ローカルの LLM が神託の文を作る）から始める。AI が動かない・応答が壊れているときは、今の文言のまま出す。

### 予言者の誤解（2026-10-13 に決定。M5 で作った）
- 神託を下してドグマが生まれたら、ローカルの LLM（Ollama の生成 API。モデルは `gemma2:9b`）に、神の意図を誤解した神託の文を頼む。モデル名・宛先・待つ秒数・吹き出しの秒数・使うかどうかは `rules.json` の `oracleAi` に置く。
- 宛先は、ループバック（`127.0.0.1`・`localhost`・`::1`）の http だけを許す。それ以外なら、起動時にデータの読み込みを失敗させる。
- LLM に渡すもの: 記号の表示名・ドグマの種別の表示名・強度、予言者の心の状態としてカオス度と調和度（新しい値は足さない。2026-10-13 に決定）。表示している言語が日本語なら日本語で、ほかは英語で答えさせる。カオス度が高いほど不吉で歪んだ文に、調和度が高いほど穏やかだが的外れな文にするよう頼み、誤解していることには触れさせない。
- 応答は JSON の `heading`（見出し）・`intent`（誤解した神の意図）・`doctrine`（歪んだ教義）とし、検証していない外部入力として扱う。3 つとも空でない文字列で、見出しは 30 字・ほかは 80 字以内、改行・制御文字を含まないものだけを使う（前後の空白は取り除く）。
- できた文は、予言者の吹き出しに 20 秒出し、年表のドグマの行に添えてセーブに残す（`saveVersion` 9）。読み込むときも同じ検証をする。
- LLM が使えないとき（使わない設定・つながらない・60 秒を過ぎた・HTTP のエラー・形の崩れ）は、ドグマの種別ごとの定型文（翻訳ファイルの `ORACLE_FALLBACK_*`）を吹き出しに出す。年表には残さない。
- 待っている間は、吹き出しに「予言者は神託を紡いでいる…」を出す。ゲームは止めない。
- 頼むのは一度に 1 つで、待っている間に次の神託が下されたら順に頼む。吹き出しには、いちばん新しい神託の文だけを出し、前の神託の文は年表に添えるだけにする。世界再創生・読み込みで年表の行が入れ替わっていたら、届いた文は捨てる。
- 吹き出しは PC の画面だけに出し、スマホには送らない（通信の形は変えない）。
- 記録（ログ）: できたら `event=oracle_generated`（`Info`。`durationMs` つき）、失敗したら `event=oracle_ai_failed`（`Warn`。`reason` は `connection_failed`・`timeout`・`http_error`・`invalid_response`）。

### 歴史の神話化（2026-10-13 に決定。M5 で作った）
- 年表の章（100 年ごと・崩壊・再創生で閉じる。[星の年表](history.md)）が閉じたら、ローカルの LLM（予言者の誤解と同じ `oracleAi` の設定）に、章の神話の文を頼む。
- 頼みに渡すもの: 章の年（始まりと終わり）、カオス度の変化（始まり → 終わり）、章の中の年表の行（表示している言語の文、新しい順に 20 行まで。仮）、前の章の神話の見出し（新しい順に 3 つまで。仮。年つき）。語りは「古い言い伝えは細部が欠けて変わった神話として織り込め」とする。
- 応答は JSON の `heading`（章の題・30 字以内）と `body`（神話の本文・200 字以内）。外部入力として、予言者の誤解と同じ形で検証する（前後の空白は取り除く。空・上限超え・改行・制御文字は使わない）。
- できた文は、章の行に添えて保存する（`saveVersion` 10）。年表の欄では、章の行に「章「見出し」」と本文を出す。できなかった章は、記録だけを残す（章の行はそのまま）。
- 頼むのは一度に 1 つ。読み込んだ後は、神話の文が無い章をもう一度頼む。ゲームは止めない。ログ: `event=myth_generated`（`Info`）・`event=myth_ai_failed`（`Warn`。`reason` は予言者の誤解と同じ）。
- 表現だけで、ゲームの計算には関わらない。

## 対象外

- AI の出力でゲームの数値を変えること（決定性を保つため）。
- 外部のクラウドの AI サービスへの送信（127.0.0.1 だけで通信する）。

## 未決

- **予言者の誤解の値**: 待つ秒数（60）・吹き出しの秒数（20）・文字数の上限（30・80）は AI が仮に置いた（`TODO(AI_UNSURE)`）。予言者の狂気の指標は、カオス度・調和度だけを使うと 2026-10-13 に決めた。
- **暗黒議会の節目とイベントの ID**: 「100 年ごとの節目」にコアがイベントの ID を選ぶ仕組みは、まだ無い。ID の一覧、選び方、それぞれの効果を決める。
- **周回の終わり**: 「1000 年完走」で周回が終わる仕組みは無い。今あるのは星の崩壊と世界再創生だけである。崩壊の後の世界再創生を「次の周回」とみなすか。聖遺物 LoRA を周回をまたいで残す置き場所（セーブとは別か）も決める。
- **既定の絵**: 生成中・失敗時に出す「既存の 32px の基本アセット」は無い。今の地表のタイルは 16px の色の仮置きで、予言者の絵だけがある。既定の絵を用意するか、今の仮置きで代えるか。地表のタイルを 32px に揃えるかも決める。
- **生成した絵をどこに置くか**: 地表のどこに、いくつ、いつまで置くか。地表に置くことがゲームの計算に関わらないこと（見た目だけ）を確かめる。
- **画像生成の依存とライセンス**: SD1.5・SDXL のモデル、LoRA、DB16 への減色や背景の透過に使う ComfyUI のカスタムノードのライセンスと出典を、取り込むときに報告し [credits.md](../credits.md) に書く。生成した絵を配布物に含めてよいかも確かめる。
- **AI の語り口を前の周回で変えること**: 決定性の境界の外（表現だけ）に収まるか。
- **創世図鑑**: スマホの「創世図鑑」の仕様が無い。
- **用語**: 方針の文書にある `DreamNodeSwap` は、用語集では「改ざん（Tampering）」と呼ぶ。予言者の誤解・暗黒議会・歴史の神話化・聖遺物・創世図鑑を用語集に足すか。
- **AI クライアントの置き場所**: 予言者の誤解では、頼みの文の組み立てと応答の検証をコア（`OracleProphecy`。I/O をしない）に、HTTP の通信を Godot 側（`OracleView`）に置いた。ほかの仕組みでも同じにするか。以下は前の検討: コア（`src/TheogonyX.Core/`）・Godot 側・別のプロセスのどれに置くか。コアは Godot に依存させず、決定的に保つので、HTTP の I/O をコアに入れるかも決める。指示書のインターフェース案は `TheogonyX.Core.Services` に置いて `ImageTexture`（Godot の型）を返すので、そのままではコアが Godot に依存する。Godot 側に置くか、コアからは PNG のバイト列を返す形にする。
- **セーブの形**: 予言者の誤解の文は、年表のドグマの行に残した（`saveVersion` 9）。画像のパスを残すときもセーブの形が変わる（`saveVersion` を上げる。[save-data.md](save-data.md)）。
- **依存関係とポリシー**: 予言者の誤解は .NET に入っている `HttpClient` と `System.Text.Json` だけを使い、パッケージは足さなかった。[AI_USAGE_POLICY.md](../AI_USAGE_POLICY.md) にローカルの Ollama を足した。画像生成に着手するときも同じように報告する。
