# 0001: シミュレーションを Godot に依存しない C# ライブラリ `TheogonyX.Core` に分け、xUnit でテストする

## 背景
夢の解釈・ドグマ・時代跳躍などのシミュレーションは、分岐と数値の境界が多く、ゲームの面白さを左右する。これを Godot のノードの中に書くと、テストのたびに Godot を起動する必要があり、確認が遅く CI も重くなる。また、同じシードからは同じ結果になること（決定性）を確かめにくい。

## 決定
- シミュレーションは `src/TheogonyX.Core/`（`net10.0` のクラスライブラリ）に置き、Godot の API・型を使わない。
- コアはファイルを読まず、ログも出さない。ゲームデータ定義は引数で受け取り、結果は戻り値か引数のオブジェクトで返す。
- 自動テストは `tests/TheogonyX.Core.Tests/`（xUnit）でコアだけを対象にし、`dotnet test` で Godot なしに実行する。
- Godot 側（`game/`）はコアを呼び、結果を表示するだけにする。Godot 上の動作は手動テストで確かめる。

## 検討した他の案
- **コアを分け、さらにシーン・ノードの結合テストを GdUnit4 で書く**: Godot の起動が必要で CI が重くなる。Phase 1 ではノードを薄く保ち、手動で確かめれば足りる。
- **GdUnit4 だけで、すべて Godot 上でテストする（コアを分けない）**: テストが遅く、ゲームのルールが Godot の API と混ざる。

## 結果
- シミュレーションのテストが数十ミリ秒で回り、CI でも Godot が要らない。
- コアに Godot の型（`Vector2` など）が要るときは、コア側で型を定義する手間がある。
- ノードとシーンの動作は自動テストで守られない。Godot 側にロジックが増えてきたら、GdUnit4 の導入を再検討する。
