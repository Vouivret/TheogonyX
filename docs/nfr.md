# 非機能要件

機能をまたいで守る要件をまとめる。目標値を決め、変えるのは人間である。目標値を変えたら、理由をADRに残す。「例」と付いた行は、目標値が決まったら置き換える。

## 性能
| 項目 | 目標 | 測り方 |
| :--- | :--- | :--- |
| 例: 通常画面のフレームレート | 推奨スペックのPCで 60fps を維持 | Godot のモニター（Debugger > Monitors） |
| 1 年の計算時間（推奨スペックの PC、近代のいちばん重い時代） | 50 ms 以内（2026-10-15 に人間が決定。高速の 1 秒に 10 年で、計算に 5 割の余裕を残す） | コアのベンチマーク |
| 時代跳躍（100 年）の計算時間 | 5 秒以内（上の 1 年 50 ms から。2026-10-15） | コアのベンチマーク |
| 例: 同時に描画するNPCの数 | 10,000体で 60fps | 計測用のシーン |
| 例: コンパニオンの操作がホストに反映されるまで | 同じLANで 200ms 以内 | 手動計測 |

- 計算の回し方（2026-10-15 に人間が決定）: シミュレーションは描画と別のスレッドで回し、画面は止めない。「前の年の値から地域ごとに同時に計算する」部分（気候・病・人数など）だけを並列にし、足し合わせる順番は地域の番号順に固定する。乱数は地域ごとに作る。並列でも 1 本でも同じ結果になることをテストで確かめる（決定性。`project.md` 3 章）。
- 人のまとまりの数には、上限を置かない（2026-10-15 に人間が決定）。重くなったら考える。

## 安定性
| 項目 | 目標 |
| :--- | :--- |
| セーブデータ | 書き込み中に終了しても、直前のセーブデータが壊れない（`.agent/rules/save-data.md`） |
| 例: 長時間の放置 | 星の崩壊まで放置してもクラッシュ・メモリの増え続けが無い |

## セキュリティ
- コンパニオンとの通信は、ペアリング（トークンの照合）を済ませた接続だけを受け付ける。
- WebSocket サーバーは、既定で同じLANからの接続だけを受け付ける。
- 例: インターネット越しの接続は対応しない

## 対応言語

## 対応環境とサポート期限
使っているランタイム・エンジン・OS・ブラウザと、そのサポート期限。年1回見直し、期限が1年以内に切れるものは移行計画を立てる。

| 種類 | 名前とバージョン | サポート期限 | 移行計画 |
| :--- | :--- | :--- | :--- |
| ゲームエンジン | Godot 4.7.2 .NET 版（`C:\Tools\Godot` に配置） | 次の 4.x 安定版が出るまで（Godot は固定の期限を出していない） | 4.x の新しい安定版が出たら、更新するかを判断する |
| ランタイム | .NET 10（LTS。SDK 10.0.401、`TargetFramework` は `net10.0`） | 2028-11-10 | なし |
| OS（ホスト） | Windows 10 / 11（64bit） | Windows 10 は延長セキュリティ更新のみ | 未定 |
| ブラウザ（コンパニオン） | iOS Safari / Android Chrome の最新版 | — | — |
