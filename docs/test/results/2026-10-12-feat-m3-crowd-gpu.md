## 計測の結果（TS-crowd-011）

| 方式 | 人数 | 1 歩の計算（GPU は読み戻しを含む） | バッファの書き込み | フレームレート |
| :--- | :--- | :--- | :--- | :--- |
| CPU | 10,000 | 0.309 ms | 0.199 ms | 1,731.5 fps |
| GPU | 10,000 | 0.687 ms | 0.202 ms | 1,009.8 fps |
| CPU | 50,000 | 1.533 ms | 1.160 ms | 357.7 fps |
| GPU | 50,000 | 0.817 ms | 1.164 ms | 475.5 fps |
| CPU | 100,000 | 3.065 ms | 2.307 ms | 182.0 fps |
| GPU | 100,000 | 1.702 ms | 2.338 ms | 239.4 fps |

- 10,000 人では、GPU 版は送り出しと待ち・読み戻しの手間の分だけ CPU 版より遅い。50,000 人以上で GPU 版が速くなる。
- どちらの方式でも、MultiMesh へのバッファの書き込み（CPU）が人数に比例して残る。

## 突き合わせの結果（TS-crowd-009）

| 区切り | 歩数（通算） | 差の最大値（タイル） |
| :--- | :--- | :--- |
| 散策（初期の地表） | 600 | 7.63e-6 |
| 散策（左半分が焦土） | 900 | 7.63e-6 |
| 狂乱 | 1,200 | 4.77e-6 |
| 停止 | 1,200 | 0 |
| 狂乱の後の散策 | 1,500 | 7.63e-6 |
| 世界再創生の後の散策 | 120 | 7.63e-6 |

- 送り直さずに長く動かすと、狂乱の後の散策で差が 0.99 タイルまで広がった（地表の上端での跳ね返りの判定が、小さな差で分かれるため）。この結果から、突き合わせを「8 歩ごとに CPU 版の状態を送り直す」形にした（AC-crowd-021）。
